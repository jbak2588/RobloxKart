# 시승장 타원형 개편 및 봇 아이템 연습 검토

기준 커밋: `723269277f81b9e0283acaba5aa821eabdc96483`.
작업 전 origin fetch 및 `origin/prototype/kart-physics`와 동일 HEAD를 확인했다.
기존 추적 파일 변경은 없었으며, 기존 미추적 아티팩트는 보존했다.

사용자 확인 범위: **시승장 형상 개편은 구현, 아이템은 가능 여부·구현안 검토까지**.
이번 작업에서 아이템 기능은 켜지 않았다. Roblox Publish도 하지 않았다.

## 구현한 시승장

- 기존 날개형 확장부와 뒤쪽 연결부의 합집합을, 매끈한 타원형 외곽과 둥근
  중앙 섬을 가진 하나의 연속 도로로 교체했다.
- 첨부 이미지에 맞춰 어두운 아스팔트, 청록색 양쪽 경계와 보행 연결을 사용한다.
  기존 줄무늬 울타리와 구워 넣은 정적 타이어 자국은 제거했다.
  실제 주행 중 Drift 자국·연기와 시연 봇은 유지한다.
- 중앙 로비 건물/보행 공간은 도로에서 제외한다. 기존 건물·Spawn·카트 시작점은
  이동하지 않는다. 도로 시각 형상, 진입 허용 영역과 충돌 경계가 같은 기하를 쓴다.
- 기존 월드 범위 X -230..450 / Z 676..1018을 유지한다. Practice 트랙과 분리된다.
- 청록색 경계에서 실제 카트 전용 충돌 경계까지 20스터드의 잔디 안전 여유가 있다.
  경계 폭 1.5 / 충돌벽 폭 2를 뺀 직선 최소 여유는 18.25스터드다.
  곡선 샘플에도 최소 여유가 확보되는지 검사했다. 기존 경계 탈출/복귀 처리는 유지한다.
- 모바일 입력·카메라·시승 속도/Drift/Mini Boost 수치와 정식 레이스 코드는 변경하지 않았다.

형상 미리보기: `artifacts/lobby-reference-oval/oval-preview.png`.
실제 Builder로 생성한 네이티브 모델: `artifacts/lobby-reference-oval/REFERENCE_OVAL_ZONE.rbxm`.
미리보기는 생성된 형상을 위에서 그린 검토도이며 Studio 화면 캡처가 아니다.
중앙 건물은 위치 확인용 평면 도형으로 표시했다.

## 아이템 사용 가능 여부: 가능, 단순 허용 플래그 변경으로는 불가

현재 `LobbyDemoService`는 서버에 시작 시각과 KartId가 담긴 Folder만 만든다.
`LobbyDemoController`가 각 클라이언트에서 `LobbyDemoRoute.sample()`에 따라 봇을
그린다. 이 봇은 전투 가능한 서버 레이서가 아니며, 서버 KartContext·RaceSession·
RacePosition·피격 상태를 갖지 않는다. 모델은 비충돌/비접촉/비쿼리다.

정식 `RaceItemController`는 같은 RaceSession의 RACING 레이서와 실제 RaceKart를
요구한다. 미사일은 바로 앞 순위, 썬더는 앞선 순위들을 서버에서 선택한다.
현재 시연 봇에는 이 조건들이 없다. GARAGE를 RACING으로 바꾸거나, 클라이언트가
명중/대상/잔량을 보내게 하거나, 가짜 Player를 RaceSession에 넣는 방식은 사용하지 않는다.

### 제안 구조

1. **서버가 관리하는 시승 전투 대상**: 기존 봇의 경로를 서버도 샘플링하고,
   식별자·위치·상태·세대 번호를 관리한다. 클라이언트는 이 상태를 보간해 그린다.
   피격 후 진행 시간도 서버에서 관리해야 화면과 판정이 엇갈리지 않는다.
2. **시승 전용 전투 어댑터**: 기존 투사체·hazard·면역·쉴드·효과/연출을 공통
   전투 대상 인터페이스로 연결한다. 정식 레이스 참가/방/보상/결과 로직과 분리한다.
   기존 서비스가 가진 getKart/getSession/resolve 주입 구조를 활용할 수 있으나,
   실제 Player/KartContext에 결합된 부분은 먼저 분리해야 한다.
3. **봇만 유효한 타격 대상**: 다른 시승자, 보행자, 전시 카트나 정식 레이스는
   공격하지 않는다. 서버는 현재 시승 기록, generation, 탑승·생존 상태, 아이템 ID,
   충전/재사용 대기, 거리/경로와 활성 효과 수를 검증한다.
4. **5개 전술 아이템 모두 표시**: 슬릭/쉴드/미사일/스모크/썬더를 선택 과정 없이
   시승 전용 직접 사용 버튼으로 제공하고 니트로 버튼/충전 게이지는 별도로 둔다.
   모바일은 2행 3열 등의 별도 레이아웃을 실제 안전 영역에서 검증한다.
   정식 레이스의 4슬롯, 키 1–4 및 기존 HUD는 유지한다.
5. **종료/세대 변경 정리**: 하차·사망·선택 변경·로비 복귀·레이스 이동·서버 이탈 시
   투사체, hazard, 효과, 아이템 상태와 이전 요청을 정리한다. Inventory/DataStore/
   Cash/XP/승패/영구 보상은 지급하지 않는다.

### 아이템별 실제 연습 의미

| 기능 | 구현 방향 및 확인할 점 |
| --- | --- |
| 슬릭 | 플레이어 뒤에 배치한 hazard를 서버 봇 경로와 swept 판정하고, 명중 시 봇의 미끄러짐/회전·회복을 표시한다. 봇이 따라오는 패턴이 있어야 맞히는 연습이 쉽다. |
| 미사일 | 서버가 시승 봇을 고정 대상으로 선정한다. 실제 경고·비행·명중·피격 감속을 연결한다. 자유 주행에는 RacePosition이 없으므로 연습용 대상 규칙이 필요하다. |
| 썬더 | 같은 시승 전투 범위의 봇을 서버가 스냅샷해 경고/낙뢰/피격을 처리한다. 자유 주행용 대상 규칙을 따로 명시한다. |
| 스모크 | 같은 구름은 봇에 한 번만 판정한다. 현재 봇은 고정 경로를 그리므로 가림을 인지하지 않는다. 스모크는 원래 시야 전용이며 감속을 임의로 추가하지 않는다. 봇의 인지 반응을 별도 구현하거나 구름/명중 상태 관찰용임을 명확히 한다. |
| 쉴드 | 켜기/지속시간은 가능하지만, 현재 봇은 공격하지 않아 차단 연습은 성립하지 않는다. 봇의 예고된 연습 공격이나 별도 공격 시험 동작을 함께 제공하는 것을 권장한다. |
| 니트로 | 기존 시승의 성공한 Mini Boost 발생을 서버에서 세어 5 BOOST마다 1개를 지급하고 별도 버튼으로 사용한다. 단순 Drift 충전/시도는 세지 않는다. |

### 반복 니트로 계약

- 성공한 BOOST 5회마다 +1, 횟수 제한 없음, 보유 최대 2, pending 최대 1.
- 보유 2 상태에서 5/5이면 pending을 하나만 유지하고 추가 BOOST는 누적하지 않는다.
- 유효한 사용만 소비하고, 2→1 소비와 pending 정산 1→2를 원자적으로 처리한다.
  거절된 사용은 소비/정산하지 않는다.
- 전투 중단/같은 시승의 복귀는 누적 상태를 보존하고 복귀 자체가 충전하지 않는다.
  시승 종료·다른 세대·레이스 이동은 초기화한다.
- `RaceLoadout`은 현재 정확히 4슬롯을 검증하므로 6개 ID를 그대로 넣을 수 없다.
  보상 전이 로직을 공통 순수 모듈로 추출하고, 레이스는 기존 RaceLoadout이,
  시승은 별도 TrainingLoadout이 각 모드의 상태를 단독 소유하도록 구현하는 안을 권장한다.
  중복 보상 카운터나 HUD 속성을 권한 원본으로 추가하지 않는다.
- 초기 니트로를 정식 레이스처럼 1개 줄지, 5 BOOST 획득 체험을 위해 0개로 시작할지는
  구현 전 선택할 정책이다. “5회마다 +1” 규칙과는 별개다.

추가로 정할 정책은 전술 아이템의 사용 후 재충전 방식/대기시간, 자유 주행의
미사일·썬더 대상 조건, 봇의 역공 제공 여부다. 검토 단계에서 임의로 고정하지 않았다.
